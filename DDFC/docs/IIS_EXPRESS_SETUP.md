## How to Run

### Option 1: Visual Studio
1. **Open the solution** in Visual Studio 2022
2. **Select "IIS Express"** from the debug profile dropdown (top toolbar)
3. **Press F5** or click the green "IIS Express" button
4. The browser will automatically open to the Swagger UI

### Option 2: Visual Studio Code
1. Open the Command Palette (`Ctrl+Shift+P`)
2. Select **".NET: Generate Assets for Build and Debug"**
3. Update `.vscode/launch.json` to use IIS Express:
```json
{
  "name": "Launch with IIS Express",
  "type": "coreclr",
  "request": "launch",
  "preLaunchTask": "build",
  "launchSettingsProfile": "IIS Express"
}
```
4. Press `F5` to start debugging

### Option 3: Command Line
From the `src\DDFC.API` directory:
```bash
dotnet run --launch-profile "IIS Express"
```

## Available Profiles

The API now has **three launch profiles**:

### 1. **IIS Express** (NEW)
- Uses IIS Express as the web server
- Best for: Testing in an environment similar to production IIS
- URL: `https://localhost:44321` or `http://localhost:21547`
- Opens browser to Swagger UI automatically

### 2. **https** (Kestrel HTTPS)
- Uses Kestrel web server with HTTPS
- Best for: Development and debugging
- URL: `https://localhost:7016` (primary) or `http://localhost:5054` (fallback)
- Browser does not open automatically

### 3. **http** (Kestrel HTTP only)
- Uses Kestrel web server without HTTPS
- Best for: Quick testing without SSL
- URL: `http://localhost:5054`
- Browser does not open automatically

## Testing the API

Once running in IIS Express, the Swagger UI will be available at:

**HTTPS:** https://localhost:44321/swagger  
**HTTP:** http://localhost:21547/swagger

### Test Endpoints

1. **Health Check** (if available):
   ```
   GET https://localhost:44321/api/health
   ```

2. **Swagger JSON**:
   ```
   GET https://localhost:44321/swagger/v1/swagger.json
   ```

3. **Login (to get JWT token)**:
   ```
   POST https://localhost:44321/api/v1/auth/staff/login
   Content-Type: application/json

   {
     "email": "admin@ddfc.com.pk",
     "password": "Admin@2026!"
   }
   ```

4. **Get Packages** (requires authentication):
   ```
   GET https://localhost:44321/api/v1/packages
   Authorization: Bearer {your-token}
   ```

## Troubleshooting

### Port Already in Use
If ports `21547` or `44321` are already in use, you can change them in `launchSettings.json`:
```json
"iisSettings": {
  "iisExpress": {
    "applicationUrl": "http://localhost:YOUR_PORT",
    "sslPort": YOUR_SSL_PORT
  }
}
```

### SSL Certificate Trust Issues
If you get SSL certificate warnings:
```bash
dotnet dev-certs https --trust
```

### IIS Express Not Installed
IIS Express comes with Visual Studio. If not installed:
- Install Visual Studio 2022 with **ASP.NET and web development** workload
- Or download IIS Express separately from Microsoft

### Database Connection Issues
Ensure your SQL Server is running and the connection string in `appsettings.json` is correct:
```json
{
  "ConnectionStrings": {
    "Default": "Server=.;Database=DDFC;Integrated Security=True;TrustServerCertificate=True;"
  }
}
```

### Migrations Not Applied
The app automatically runs migrations on startup. If issues occur:
```bash
cd src\DDFC.Infrastructure
dotnet ef database update --startup-project ..\DDFC.API
```

## Environment Variables

When running in IIS Express, the environment is set to **Development** by default.

To change environment:
1. Modify `launchSettings.json`:
```json
"IIS Express": {
  "environmentVariables": {
    "ASPNETCORE_ENVIRONMENT": "Staging"
  }
}
```

Available environments:
- `Development` - Full error details, Swagger enabled
- `Staging` - Limited error details
- `Production` - Minimal error details, Swagger disabled
