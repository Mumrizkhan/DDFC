## Why Admin Dashboard Returns 403

### Root Cause Analysis

Your JWT token **does not contain** the required `role: "Admin"` claim, even though the user is authenticated.

### The Flow:

```
1. Admin logs in ? ? Authenticated
2. JWT token created
3. Token includes: email, name, userType, departmentCode, etc.
4. BUT missing: "role": "Admin"
5. Request sent with JWT header
6. ASP.NET Core checks policy: RequireClaim("role", "Admin")
7. Claim not found ? 403 Forbidden
```

### Policy Definition (Program.cs):
```csharp
o.AddPolicy("AdminOnly", p => p.RequireClaim("role", "Admin"));
```

### What Token Should Contain:
```json
{
  "role": "Admin",
  "permission": ["CanManageUsers", "CanManageCustomers", ...],
  "userType": "staff",
  ...
}
```

## How to Verify & Fix

### Step 1: Check JWT Token Claims
Use `AuthorizationDebugMiddleware` logs to see what claims are actually in the token.

**Look for:**
```
[AuthDebug] Claim: role = Admin
```

**If you see:**
```
[AuthDebug] Claim: role = (missing or blank)
```
? The role is not being included in JWT

### Step 2: Verify Database Seeding
Make sure the seeder runs and Admin user is properly assigned:

```sql
-- Check if Admin role exists
SELECT * FROM AspNetRoles WHERE Name = 'Admin'

-- Check if admin user is assigned to Admin role
SELECT * FROM AspNetUserRoles 
WHERE UserId = (SELECT Id FROM AspNetUsers WHERE Email = 'admin@ddfc.com.pk')

-- Check if Admin role has permission claims
SELECT * FROM AspNetRoleClaims 
WHERE RoleId = (SELECT Id FROM AspNetRoles WHERE Name = 'Admin')
```

### Step 3: Reseed Database
Delete old database and let seeder run fresh:

```bash
# Option 1: Local dev with SQLite
dotnet ef database drop --project src/DDFC.Infrastructure -s src/DDFC.API
dotnet ef database update --project src/DDFC.Infrastructure -s src/DDFC.API
dotnet run --project src/DDFC.API

# Option 2: With SQL Server
# Drop database in SQL Management Studio, then run above commands
```

### Step 4: Test Admin Access
1. Login as admin@ddfc.com.pk
2. Copy JWT token from response
3. Check logs: should see `[AuthDebug] Claim: role = Admin`
4. Call `/api/v1/admin/dashboard` with token
5. Expected: 200 OK
